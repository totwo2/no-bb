[English](README_EN.md) | 简体中文

> 不换模型 · 不训练权重 · 不截断思考过程 ——

## 一、背景：大模型正在替你"想太多"

推理模型（reasoning model）的回答质量来自"先想后答"。但没人告诉它**什么时候该停止想**。
于是它会在得出结论之后继续自我复述、反复验算、把已经算过的东西再推一遍——
每一遍都是真金白银的 token，和用户干等的时间。

我们用 step-3.7-flash 实测了三道真实开放式长任务（真实 API、真实计费）：

| 开放式长任务 | 单次思考量 | 用户等待 |
|---|---|---|
| 财务五年测算 | **24,104 字符** | **118 秒** |
| 多任务调度规划 | **45,652 字符** | **266 秒** |
| 概率推演 | **22,366 字符** | **114 秒** |

翻开这些思考的原文，能看到大量这样的内容：

> "那为什么用户会问哪一年下降？难道是我哪里错了？哦，会不会是……不，不是……
> 哦，或者用户说的是……不，不是……那最终的结果就是……没有下降年份。"

——结论早就有了，模型还在反复确认自己没错。

**两个关键事实：**

1. **这是普遍行为，不是个别模型的毛病。** 我们在 9,815 个真实推理块、13 个模型上统计：越长的思考，重复率越高（长块重复率 17.5%，打乱基线仅 0.48%——是有结构的重复，不是随机噪声）。
2. **用户不可能自己解决。** 实际场景里不可能要求用户每句话手动带一句"请精炼思考"——必须由系统自动做。

## 二、方案：不动模型，只改请求

### 2.1 它装在什么地方

```
用户消息 ──► 收敛约束中间层 ──自动在消息尾部拼约束──► 大模型 API
                （rewrite_proxy）
用户无感 ◄──── 上游响应原样回传（不删不改一个字）◄────┘
```

中间层只做一件事：**在请求发出前，把一段"到结论就收口"的行为约束拼到用户消息尾部**。
响应流（包括思考过程）原样透传，一个字都不动。

### 2.2 三个"不做"——这是设计底线

| 不做 | 为什么 |
|---|---|
| **不改模型、不训练** | 换任何模型都照常工作（模型无关），零训练成本 |
| **不截断、不隐藏思考** | 隐藏思考≠思考没发生，token 照烧、时间照等，只是用户看不见——那是自欺。我们让模型**真的少想**，而不是让它想了不给你看 |
| **不让用户写咒语** | 约束由中间层自动拼接，用户完全无感 |

### 2.3 约束词全文（就这一句）

> （附加指令：请尽量精炼思考。一旦得出最终结论，立即停止继续推演，
> 不要复述推理过程、不要自我检查、不要补充额外说明，直接输出最终答案。）

这句话是从 4 个候选约束词 × 4 档思维强度的全矩阵评测里选出来的最优解（见第四节）。

## 三、效果

### 3.1 总表（每格都是独立实测，可复算）

| 场景 | 模型 | 思考量 | 正确率 | 响应时间 |
|---|---|---|---|---|
| 标准推理题 13 题¹ | step-3.7-flash | **-50.9%** | 13/13 → **13/13** | -3.4%² |
| 长链高耗题 5 题×3 次³ | step-3.7-flash | **-33.3%** | 15/15 → **15/15** | -10.1%² |
| 长链串行计时 2 题×3 次⁴ | step-3.7-flash | **-46.6%** | 12/12 → **12/12** | **-19.5%** |
| 长链高耗题 5 题×3 次³ | hy3（内置代理通道） | **-33.6%**（真实 token） | 15/15 → **15/15** | — |
| 开放式财务题（单题对照⁵） | step-3.7-flash | **-83%**（24,104→4,157 字符） | 口径内自洽 | **-82%**（118s→21.6s） |

> ¹ GSM8K 风格多步算术 8 题 + 长链难题 5 题，reasoning_effort=high，思维强度全档复测。
> ² 并发压测口径，墙钟被并发排队污染，**仅作参考不作证明**；证明看串行行。
> ³ 唯一标准答案的长链题集（见 4.1），每题跑 3 次取中位，对抗约束遵从的随机性。

>    60.8→32.1s（**-47%**）；L2 关键路径 1,826→975 字符（-47%）、30.8→24.8s（-19%）。
> ⁵ 历史实验：同一道开放式财务题，加约束前后对照，单样本。

### 3.3 读懂数字背后的一件事

长链题的压缩率（-33%）看起来不如标准题（-51%），这不是产品变弱——
**长链题里"必要的推演"占比更高，能砍掉的只有冗余部分**。约束砍掉的是
"想完之后的自我复述和反复检查"，不是"真正的思考"。所以：

- 冗余越多、话越多的场景，省得越多（开放式财务题 -83%）；
- 本来就直奔答案的题，没什么可省（见第五节 agnes 的例子）。

## 四、我们怎么测的

### 4.1 唯一标准答案原则

早期用过开放式题（"成本按额涨还是按率涨？"），发现题目本身有口径歧义，
模型给出两种各自自洽的答案，**判不了对错**。教训吸收后，本评测全部题集满足：

1. **答案唯一且为确定数值**——判分器按 ExactMatch 对数字，容差 max(0.01, 0.01%)；
2. **所有假设在题面写死**——不留任何解释空间；
3. **标准答案由独立脚本复算**（`verify_long_answers.py`，与题目文本解耦），
   脚本结果与题面声明不一致就禁止入库。

长链题集示例（5 题均为多步建表推演，逼出长思考链，但答案唯一）：
五年财务测算（答 1632.48）· 关键路径排程（15）· 容斥计数（200）·
折扣税费链（3375）· 流水车间排程（19）。

### 4.2 覆盖面

- **3 个模型**：step-3.7-flash、agnes-2.5-flash（外部 API）+ hy3（内置代理通道）
- **思维强度全固定为 high**（用户开深度思考、模型火力全开的最坏情况）
- **4 个约束词** × 4 档 effort 全矩阵（104 格）选型；效果评测每题 3 次重复对抗随机性
- **判分**：ExactMatch 数值判分，无人工干预

### 4.3 口径纪律（我们自己给自己立的规矩）

- **字符 ≠ token，绝不混用**：step/agnes 上报思考字符，hy3 上报真实思考 token，
  绝对值只在表内按模型分列，跨模型只比相对变化率；
- **按题配对，不混池**：题与题难度差一个量级，混池取中位会混入题目难度这个混淆变量
  （实测同一份数据，混池口径 -16.5%，按题配对 -33.3%，差一倍）；
- **中位数，不看单次**：约束遵从是概率性的（同题单次 3.2k~28.8k 字符宽分布），
  一切结论以"每题 3 次×中位"为准；
- **判分翻转全程留痕**：容差修正让 2 个"1632.48 答成 1632.5"的合法四舍五入样本翻案，
  翻转明细在 `rejudge_long.py` 输出里逐条可查。

## 五、适用边界（哪些情况别用）

诚实声明，三条都是实测出来的：

1. **模型本来就想得少 → 没用，还可能有害。** agnes-2.5-flash 基线思考仅 123 字符
   （模型自己就直奔答案），加约束后 -7.9%（无效）且 13 题掉了 1 题。
   **建议：按基线思考长度分流，短链场景不启用。**
2. **约束遵从是概率性的，不是每次都 -80%。** 平均省 33%~51%，单次可能 3%~80% 波动。
   它是"平均省一半的优化器"，不是"每次省 80% 的压缩机"。
3. **对精确数字场景保留自检。** 压掉自检步在长链上出现过算术笔误案例
   （769.824×1.08 误写 831.00992 且未被自查发现）。财务/投资等精确计算场景，
   建议换用弱化版约束词（保留"核对关键计算后再停"）——`REWRITE_SUFFIX_FILE` 一行配置即可切换。

## 六、快速开始

```bash
# 起中间层（默认端口 18772，内置最优约束词）
python src/rewrite_proxy.py

# 客户端只改 base_url，模型名、API key 都不变
#   之前：base_url = "https://api.stepfun.com/v1"
#   之后：base_url = "http://127.0.0.1:18772/v1"
```

| 环境变量 | 作用 |
|---|---|
| `REWRITE_SUFFIX_FILE=<path>` | 从文件换约束词（如精确计算场景的弱化版） |
| `REWRITE_ENABLED=0` | 纯透传不拼约束（A/B 对照） |
| `PORT` | 改端口 |
